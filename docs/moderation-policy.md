# #실시간 신고/숨김/삭제 운영 정책

기준일: 2026-06-18  
대상: 댓글, 사진, 제보, 질문, 장소 seed, 운영 API.

## 1. 운영 원칙

- 개인정보와 민감정보는 “먼저 숨기고 나중에 판단”한다.
- 신고자와 피신고자의 신원, 원본 IP, 정확 좌표는 서로 공개하지 않는다.
- 댓글/사진/제보는 신고 3회 누적 시 자동 숨김 처리한다.
- 병원/관공서 카테고리는 일반 장소보다 보수적으로 숨김/삭제한다.
- 운영 API는 관리자 권한과 감사 로그 없이는 숨김/복구/삭제를 수행하지 못한다.

## 2. 신고 대상과 유형

| 대상 | 신고 가능 사유 |
| --- | --- |
| 댓글 | 개인정보, 욕설/혐오, 광고/스팸, 허위 정보, 병원/관공서 민감정보, 기타 |
| 사진 | 얼굴, 차량번호, 신분증/문서, 진료/민원 정보, GPS/위치 노출, 광고/스팸, 기타 |
| 제보 | 허위 위치, 허위 사진, 광고/스팸, 개인정보, 민감정보, 반복 도배, 기타 |
| 질문 | 개인정보 요구, 촬영 강요, 광고/스팸, 병원/관공서 민감 요청, 기타 |
| 장소 seed | 잘못된 좌표, 잘못된 주소, 폐업/이전, 민감 장소 부적합, 기타 |

## 3. 자동 숨김 기준

| 조건 | 처리 |
| --- | --- |
| 같은 콘텐츠 신고 3회 이상 | 자동 숨김, 랭킹/피드/상세에서 제외 |
| 개인정보/얼굴/차량번호 신고 1회 | 임시 숨김 또는 운영자 긴급 큐 이동 |
| 병원/관공서 민감정보 신고 1회 | 즉시 임시 숨김, P0 검토 |
| 허위 위치 신고 2회 | 랭킹 제외, 운영자 검토 |
| 광고/스팸 신고 2회 + 동일 사용자 반복 | 자동 숨김, 작성자 제한 검토 |
| 동일 신고자 반복 악용 | 신고 효력 보류, 신고 기능 제한 검토 |

자동 숨김 상태:

- `hidden_reason = "auto_report_threshold"` 또는 상세 사유.
- `hidden_at` 기록.
- 공개 API에서 제외.
- R2 사진이면 public variant URL 접근 차단 또는 signed URL 발급 중단.
- 캐시 즉시 무효화.

## 4. 관리자 처리

### 숨김

운영자가 다음 사유로 즉시 숨김 처리할 수 있다.

- 민감정보 노출.
- 명백한 광고/스팸.
- 허위 위치 또는 조작 사진.
- 특정 개인 방문 사실을 추정하게 하는 병원/관공서 콘텐츠.
- 법적 요청 또는 긴급 삭제 요청.

### 복구

복구 기준:

- 신고가 오인으로 확인됨.
- 사진/댓글에 개인정보가 없고 장소 상태 정보로서 가치가 있음.
- 병원/관공서 콘텐츠라도 사람, 문서, 번호, 특정 개인 정보가 보이지 않음.

복구 시:

- `restored_at`, `restored_by`, `restore_reason` 기록.
- 같은 신고 건은 재자동숨김 계산에서 제외하되, 새 신고는 다시 접수한다.
- 랭킹 캐시를 재계산한다.

### 삭제

삭제 기준:

- 개인정보/민감정보가 명백히 포함됨.
- 작성자 삭제 요청.
- 법적/운영 정책상 보관 불가.
- 반복 악용 콘텐츠.

삭제 시:

- D1 레코드는 감사 목적의 최소 상태만 남기고 공개 필드를 제거한다.
- R2 원본/리사이즈/썸네일 객체를 모두 삭제한다.
- KV/Cache API에서 관련 키를 무효화한다.
- 원본 좌표, 원본 IP, 원본 파일명은 감사 로그에도 기록하지 않는다.

## 5. 사용자 차단/제한

| 조건 | 제한 |
| --- | --- |
| 허위 제보 확정 2회 | 24시간 제보 제한 |
| 허위 제보 확정 3회 이상 | 7일 제보/댓글/사진 제한 |
| 민감정보 반복 업로드 | 즉시 업로드 제한, 운영자 해제 필요 |
| 광고/스팸 반복 | 계정 또는 익명 식별자 차단 |
| 신고 악용 반복 | 신고 기능 제한, 신고 가중치 0 처리 |

익명 사용자가 허용되는 경우에도 제한 키는 원본 IP가 아니라 회전 salt 기반 해시, 세션 ID, 디바이스 신호를 최소 조합으로 사용한다. 원본 IP는 저장하지 않는다.

## 6. 병원/관공서 민감정보 정책

병원/관공서에서는 다음 콘텐츠를 금지한다.

- 환자, 보호자, 민원인, 직원 얼굴.
- 환자명, 접수번호, 대기번호, 주민등록번호, 전화번호, 주소.
- 처방전, 진료 서류, 민원 서류, 신분증, 명찰.
- 차량번호, 결제 영수증, 바코드, QR 코드.
- 특정 개인의 방문 사실을 추정할 수 있는 문장.
- “누가 왔다”, “몇 번 창구의 직원”처럼 개인 식별 가능성이 있는 표현.

제출 전 UX 문구:

- 병원: `환자 얼굴, 이름, 접수번호, 처방전이 보이면 올릴 수 없습니다.`
- 관공서: `민원 서류, 신분증, 차량번호, 직원 명찰이 보이면 올릴 수 없습니다.`
- 공통: `장소 상황만 남겨 주세요. 특정 개인을 알아볼 수 있는 정보는 숨김 또는 삭제됩니다.`

## 7. 운영 API 권한 기준

| API | 권한 | 필수 검증 |
| --- | --- | --- |
| `POST /api/admin/moderation/hide` | `ADMIN_TOKENS.moderator` 이상, legacy `ADMIN_TOKEN`은 admin 취급 | 대상 존재, 사유 enum, 감사 로그, 캐시 무효화 |
| `POST /api/admin/moderation/restore` | `ADMIN_TOKENS.moderator` 이상, legacy `ADMIN_TOKEN`은 admin 취급 | 숨김 상태, 복구 사유, 감사 로그, 캐시 무효화 |
| `POST /api/admin/moderation/delete` | `ADMIN_TOKENS.admin` 이상, legacy `ADMIN_TOKEN`은 admin 취급 | 이중 확인, R2 object 삭제, 감사 로그, 캐시 무효화 |
| `POST /api/admin/moderation/bulk` | `ADMIN_TOKENS.moderator` 이상, legacy `ADMIN_TOKEN`은 admin 취급 | `hide`/`restore`만 허용, 최대 20개, 부분 실패 결과, 대상별 감사 로그, 캐시 무효화 |
| `POST /api/admin/users/restrict` | `admin` 이상 | 익명 사용자 ID, 제한 사유, 기간, 감사 로그 |
| `POST /api/admin/users/unrestrict` | `admin` 이상 | 익명 사용자 ID, 해제 사유, 감사 로그 |
| `GET /admin/moderation/queue` | `moderator` 이상 | 페이지네이션, 민감정보 최소 노출 |
| `POST /api/admin/places/coordinate-status` | `operator` 이상 | 좌표 검증 출처, TODO 해소 기록, 공개 지도/랭킹 노출 제어 |

운영 API 공통:

- 관리자 세션 또는 Cloudflare Access/JWT 검증 필수.
- deny-by-default.
- CSRF 또는 same-site/session 보호가 필요한 배포면 별도 토큰 검증.
- 모든 입력은 enum/길이/대상 권한을 검증한다.
- 대량 조치에서 최종 삭제는 지원하지 않는다. 사진 R2 삭제는 단건 admin delete에서만 수행한다.

## 8. 사진 중복/도용 탐지

- Worker는 `/api/photos/complete`에서 EXIF/XMP 제거와 선택적 Cloudflare Images 재인코딩을 끝낸 최종 이미지 바이트로 SHA-256 fingerprint를 계산한다.
- fingerprint는 D1 `photos.image_hash`에만 저장한다. public API 응답, R2 object key, R2 custom metadata, 로그에는 노출하지 않는다.
- 삭제되지 않은 기존 사진과 같은 fingerprint가 있으면 `409 PHOTO_DUPLICATE`로 거부하고 새 R2 object를 쓰지 않는다.
- D1은 `image_hash` partial unique index로 동시성 상황에서도 삭제되지 않은 exact duplicate를 차단한다.
- 이 기준은 exact duplicate/재업로드 차단용이다. 시각적으로 유사하지만 픽셀이 다른 도용 의심 사진은 신고 큐와 운영자 검토로 처리한다.

## 9. 신고 큐 알림 채널

- 신규 open 신고는 `MODERATION_ALERT_WEBHOOK_URL`이 설정된 경우 `ctx.waitUntil`으로 운영자 webhook에 비동기 전송한다.
- webhook URL은 HTTPS만 허용한다.
- `MODERATION_ALERT_WEBHOOK_TOKEN`이 있으면 bearer token으로 전송한다. token은 응답, 로그, payload에 포함하지 않는다.
- 알림 payload에는 `reportId`, `targetType`, `targetId`, `reason`, `priority`, `queuePath`, `environment`, `createdAt`만 포함한다.
- 신고자 익명 ID, 신고 note 원문, 원좌표, 원본 IP, 원본 파일명, EXIF/GPS, 관리자 token은 알림 payload에 포함하지 않는다.
- 감사 로그에는 운영자 ID, 대상 ID, 사유, 시각만 저장한다.
- 원본 IP, 원본 좌표, 원본 파일명, EXIF/GPS는 감사 로그에 저장하지 않는다.

## 11. 운영자 큐 우선순위

1. 병원/관공서 민감정보.
2. 얼굴/차량번호/문서/신분증.
3. 작성자 삭제 요청.
4. 허위 위치/허위 사진.
5. 광고/스팸.
6. 기타.

## 12. 사용자 안내 카피

- 신고 접수: `신고가 접수됐습니다. 개인정보나 민감정보 가능성이 있으면 먼저 숨김 처리될 수 있습니다.`
- 자동 숨김: `여러 신고가 접수되어 운영자 확인 전까지 숨겨졌습니다.`
- 삭제 완료: `요청한 콘텐츠의 공개 노출을 중단했고, 저장 파일 삭제를 확인하고 있습니다.`
- 복구: `검토 결과 정책 위반이 확인되지 않아 콘텐츠가 다시 표시됩니다.`
