## 0. 실행 현황

2026-07-20 현재 핵심 전국 탐색·검색·지도 fallback·장소 확정 제보·해시태그·신고·삭제·비용 보호는 로컬 구현과 `428/428` 테스트를 통과했습니다. 다만 제품 구현과 실제 출시 준비는 같은 진행률로 계산하지 않습니다.

- 제품·보안 구현: 핵심 흐름은 대부분 구현됐고, 남은 개발은 주로 live API/R2/source/push 연결과 실제 운영 증거입니다.
- Production 승격 체크리스트: 완료 6개, 부분 완료 2개, 미완료 9개입니다. 부분 완료를 0.5로 계산한 출시 준비도는 `7/17`, 약 `41%`입니다.
- 출시 판정: P0 blocker 10개가 열려 있어 `no-go`입니다. 전국 기능 방향은 유지하되 현재 정보가 없는 장소는 `최근 확인 정보 없음`으로 표시합니다.
- Cloudflare: staging D1은 `0026`까지 검증됐지만 R2는 여전히 `R2_NOT_ENABLED`이고 staging API application은 live traffic에 배포되지 않아 `/api/health`가 404입니다.
- NAVER Maps: localhost에서는 실제 NAVER 타일 13개 로드를 확인했습니다. 콘솔 hard limit은 일 `160,000`, 월 `4,800,000`, 한도 초과 사용 불가로 저장했고 일·월 `70%` 알림을 저장했습니다. 통보 대상과 소유 custom domain은 아직 없습니다.
- Staging web: 보호 모드에서 외부 지도 호출 0건을 유지하면서 `실시간 연결 다시 시도`와 정확한 보호 상태 안내를 제공하는 version `fc15d04e-6534-44d3-b908-8ce8cbb3a336`이 배포됐습니다.

## 1. 총괄 결정

`#실시간`은 특정 도시 앱이 아니라 **전국 어디서나 장소를 찾고, 최근 현장 근거가 있으면 보고, 없으면 첫 근거를 남길 수 있는 앱**으로 출시한다.

- 전국 검색·지도·장소 열람·제보 기능을 지역별로 잠그지 않는다.
- 데이터가 없는 지역에 상태나 순위를 만들지 않고 `최근 확인 정보 없음`을 표시한다.
- Tier A/B는 기능 접근 범위가 아니라 초기 사진·제보 공급과 운영 인력을 집중할 우선순위다.
- 전국 확장은 장소 수가 아니라 `최근 3시간 내 승인된 근거가 있는 장소 비율`로 판단한다.
- 핵심 약속은 “인기 장소 추천”이 아니라 **출발 전에 최근 사진과 관측시각으로 지금 상황을 확인**하는 것이다.

## 2. 사용자가 해결하려는 일

### 방문자

“지금 출발해도 되는지 결정하기 위해, 10초 안에 최근 사진·줄·혼잡·주차 근거를 보고 싶다.”

필수 결과:

1. 장소 이름과 주소가 명확하다.
2. 사진·상태마다 관측시각과 만료 여부가 보인다.
3. 근거가 없으면 모른다고 말한다.
4. 검색에서 장소 상세, 지도, 길찾기로 자연스럽게 이동한다.
5. 샘플·예상·공식 데이터·사용자 제보를 구분한다.

### 현장 제보자

“사진 한 장과 내가 실제로 본 상태만 빠르게 남기고 싶다.”

필수 결과:

1. 업로드 전에 장소를 직접 확정한다.
2. 사진, 장소, 태그, 한 줄, 올리기의 짧은 순서를 유지한다.
3. 얼굴·차량번호·서류와 운전 중 제보 위험을 즉시 안내한다.
4. 위치 인증은 선택 사항이며 정밀 좌표를 공개하지 않는다.
5. 접수·검수·승인·거절·삭제 상태를 내 활동에서 확인한다.

### 장소 운영자·지역 파트너 후보

“광고 문구가 아니라 최근 현장 근거로 방문자의 불확실성을 줄이고 싶다.”

운영자나 파트너는 아직 확보된 것으로 표현하지 않는다. 제휴 표시는 계약, 권리, 표시 기준을 확인한 뒤에만 사용한다.

North-star metric은 **Weekly Fresh Evidence Decisions**다. 최근 3시간 내 승인된 사진 또는 상태를 본 뒤 저장·공유·지도 열기·방문 결정 피드백 중 하나가 이어진 주간 세션 수로 정의한다. 원시 위치나 개인 식별값을 마케팅 KPI로 저장하지 않는다.

보조 지표:

- 검색 → 최근 근거 열람률
- 최근 근거 열람 → 지도·저장·공유 전환율
- 제보 시작 → 접수 완료율과 중앙 완료시간
- Tier A/B fresh coverage
- D1/D7 집계 재방문
- 지도 성공률과 안전 fallback률
- 신고 처리시간, 승인 전 공개 0건, 개인정보 사고 0건
- 비용 보호 자동 중단 횟수와 정상 복구 시간

## 5. 전국 집중 운영 계획

### Tier 점수

장소별 100점 가설 점수로 시작하고 실제 4주 데이터로 교체한다.

- 방문 전 불확실성 30%: 도착 전 줄·주차·혼잡을 알기 어려운가
- 상태 변동성 25%: 시간대·날씨·행사로 상황이 자주 변하는가
- 사진 의사결정 가치 20%: 사진 한 장이 방문 결정에 도움 되는가
- 공급 가능성 15%: 안전하고 반복 가능한 현장 공급 후보가 있는가
- 운영 위험 10%: 민감 장소·개인정보·신고 부하를 감당할 수 있는가

어떤 장소도 점수만으로 자동 활성화하지 않는다. 주소·좌표 검증, 촬영 권리, 운영 담당, 신고 대응 가능성을 확인해야 한다.

### 승격·강등 규칙

- Tier B → Tier A: 2주 연속 fresh coverage 70% 이상, 신고 24시간 SLA, 공급자 2개 경로 이상, 개인정보 중대 사고 0건.
- Tier A → Tier B: 2주 연속 fresh coverage 50% 미만, 반복 권리 이슈, 운영자 부재, 신고 SLA 실패.
- 어떤 Tier에서도 최근 근거가 없으면 `최근 확인 정보 없음`을 표시한다.
- 전국 사용자 기능은 Tier 강등과 무관하게 유지한다.

## 6. 디자인 계획

### 정보 구조

1. 홈: 최근 사진과 방문 판단을 먼저 보여준다.
2. 검색: 장소·지역·해시태그를 한 입력에서 탐색한다.
3. 지도: 근거가 있는 장소만 랭킹에 넣고, 근거가 없는 장소는 별도 상태로 보여준다.
4. 장소 상세: 최근 근거, 관측시각, 출처, 해시태그, 주변 장소를 한 흐름으로 연결한다.
5. 지금컷 올리기: 장소 확정 후 사진·상태를 작성한다.
6. 내 활동: 접수·검수·저장·팔로우·차단·삭제를 관리한다.

### P0 사용성 원칙

- 일반 하단 업로드 버튼은 탐색 중 기본 장소를 재사용하지 않는다.
- 사용자가 검색·지도·상세에서 직접 고르거나 업로드 장소 선택 화면에서 확정해야만 작성 폼을 연다.
- 장소가 없을 때도 잘못된 인기 장소로 연결하지 않고 검색·지도 복구 행동을 제공한다.
- 시간은 상대시간과 전체 날짜·시각을 함께 제공하고, 미래 시각을 `방금 전`으로 표시하지 않는다.
- 사진·상태·샘플·예상·공식 출처의 시각적 라벨을 일관되게 유지한다.
- 44px 이상의 터치 영역, 키보드 포커스, 스크린리더 이름, 360/390/430px 무가로스크롤을 유지한다.

현재 코드에 반영된 항목:

- 탐색용 `selectedPlace`와 업로드용 `reportPlace` 분리
- 일반 업로드 진입 시 명시적 장소 선택 게이트
- 전국 무데이터 상태의 정직한 안내
- Tier A/B fresh coverage 관리자 카드와 Tier A 70% 판정
- iOS/Android 네이티브 사진 선택 시 HEIC/HEIF를 bounded JPEG로 변환하고 JPEG magic byte까지 실패 폐쇄로 확인
- 외부 검색 결과와 분리된 수동 `장소 추가 요청` 폼, 본인 전용 상태 조회, 관리자 분류 큐, 세션당 3건/일 및 전역 1,600건/일 선차단 원장
- Workers/D1 사용량 60% 1회 경고, 70% 비필수 기능 제한, 80% 중단과 핵심 전국 조회 snapshot, 관리자 대조·재개 화면

남은 디자인·개발 항목:

1. `ready_for_manual_import`로 분류된 장소 요청의 주소·좌표를 운영자가 별도 검증한 뒤에만 공개 장소로 가져오는 staging 운영 절차와 증거를 완성한다. 현재 큐는 의도적으로 자동 등록하지 않는다.
2. `[x] 완료-local`: 지도는 사진 유무와 무관한 전체 장소 핀, 순위는 최신 근거가 있는 장소만이라는 범위를 제목·빈 상태에 맞췄고, 필터의 pressed 상태와 결과 재검색을 실제 브라우저로 검증했다. NAVER 실타일 staging 계약은 owner-domain 등록 후 남긴다.
3. `[x] 완료-local`: 해시태그 결과의 최신순 cursor pagination과 `팔로우 → 마이 → 최신 사진 다시 보기` 복귀를 390x844 실제 브라우저 클릭 하네스로 검증했다. 실제 staging 데이터·Worker에서 같은 흐름을 재검증하는 외부 증거는 남는다.
4. `[~] 완료-local / 외부 검토 대기`: 실제 UGC에는 `사용자 제보`·검수 상태·전체 관측시각을, 공식 신호에는 제공기관 attribution·관측시각·만료를 표시하며 attribution 렌더링은 샘플 ID가 아니라 데이터 필드 기준이다. 사진은 매 업로드 전에 사용자가 “직접 촬영했거나 게시 권한이 있음”과 안전 검수를 명시적으로 확인해야 파일 입력이 활성화되고, Worker는 현재 정책 버전이 없거나 거짓인 티켓 요청을 Turnstile·D1보다 먼저 거부한다. D1은 기존 `terms_acceptances`에 익명 행위자별 `community` 정책 버전을 중복 없이 기록한다. 이 확인은 실제 권리 보유를 자동 증명하지 않으므로 공급 사진별 권리 증거와 source별 법무 승인은 외부 운영 게이트로 남는다.

## 8. 개발·검증 하네스

현재 하네스를 확장해 다음을 출시 계약으로 고정한다.

1. 단위·통합: `npm test`에서 Worker, D1 migration, 익명 세션, 비용 보호, 지도·UI 계약을 검증한다.
2. SQLite 필수화: CI에서 SQLite를 설치·버전 확인하고, 누락 시 D1 테스트를 skip하지 않고 실패한다.
3. 브라우저: `scripts/cloudflare-pages-smoke.mjs`가 전국 검색, 지도 fallback, 사진·제보·신고·삭제, 관리자 KPI, 비용 중단/재개를 실제 UI에서 검증한다.
4. 장소 오인 방지: 일반 업로드 진입은 `reportPlace=null`, 명시적 선택 뒤에만 작성 폼을 허용한다.
5. Fresh coverage: 전체 참고값과 Tier A/B를 분리하고 Tier A만 70% 출시 기준을 적용한다.
6. 출시 원장: blocker는 `id`, `severity`, `status`, `owner`, `evidence`, `due`를 모두 가져야 하며 `status` 누락·오타는 fail-closed 처리한다.
7. 외부 증거: R2, D1, Turnstile, NAVER owner-domain, 실기기, 법무는 로컬 테스트와 별도 상태로 기록한다.

출시 증거는 `done`, `blocked-external`, `missing`으로 분리한다. 로컬 mock 브라우저 성공을 live staging 또는 실기기 성공으로 표현하지 않는다.

## 10. 최종 go/no-go

전국 내부 베타 시작 조건:

- Tier A 후보와 담당자가 확정되고 fresh coverage 측정이 시작됨
- staging API/D1/R2/Turnstile/NAVER 지도 증거 통과
- 승인 전 UGC 공개 0건과 신고·삭제 흐름 통과
- Android/iPhone 실제 기기 핵심 흐름 통과
- 사용자 비용 중단·운영자 재개 절차 통과

전국 공개 확대 조건:

- Tier A fresh coverage 70% 이상
- 지도 성공률 99% 이상
- native crash-free session 99.5% 이상
- 신고 24시간 이내 처리
- 제보 완료시간 중앙값 15초 이하
- 개인정보 중대 사고 0건
- 열린 P0 blocker 0개

조건을 충족하지 않아도 특정 지역으로 앱 기능을 거짓 축소하지 않는다. 대신 전국 기능은 유지하고 근거가 없는 장소는 정확히 `최근 확인 정보 없음`으로 표시하며, 현장 공급과 마케팅 집행만 검증된 권역에 집중한다.
