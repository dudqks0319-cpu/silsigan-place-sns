대상: `codex/local-live-refactor-20261124`, 기본 커밋 `a325c3d29aad3d9e8b3df7fecb19083397bb1b1a` 이후의 지역 정보 리팩토링.

## 현재 판정

**기능 코드는 로컬 통합 검증을 통과했다. 운영 배포 승인은 완료되지 않았다.** 실제 공급자 키로 확인한 결과, 브라우저 화면 검수, 의존성 보안 수정은 남아 있다. 이 기록의 성공 항목은 그 범위를 대신하지 않는다.

검증 환경은 Node.js 24.22.3이었다. CI는 Node.js 22와 고정한 pnpm 10.11.0에서 frozen install, `pnpm verify`, HTTP smoke를 실행하도록 추가했다. 별도 `dependency-audit` job은 `pnpm audit --audit-level low`를 실행하고 남은 취약점을 실패로 표시한다. 현재 의존성은 이 보안 조건을 충족하지 못한다. **CI 실행 결과는 PR의 Checks에서 별도로 확인해야 한다.**

## 의미 있는 실패·경계 검증

- 지역·카테고리 허용 목록, 검색어 길이와 원본 GPS 입력 거부.
- 기상청 격자 변환, 한국 시각의 일/연도 경계와 발표 대기 시간.
- 원본 관측 시각 기준의 최신/이전/만료 구분. 미래·결측·24시간 초과 자료를 현재 값으로 변환하지 않음.
- `NO_DATA`일 때만 이전 발표를 한 번 재조회. 인증·HTTP·응용 오류·타임아웃은 안전한 빈 상태로 반환.
- 동시 공급자 요청 합치기, 캐시에서도 이미 지난 예보 시간 제거, 자격증명·외부 요청 URL이 사용자 오류에 포함되지 않음.
- 카카오 분류별 부분 실패에서도 성공 결과 유지, 잘못된 좌표와 응답 제외. 어린이 키워드를 검증된 시설 정보로 취급하지 않음.
- 에어코리아 지정 측정소 필요, 점검/결측값은 `null`, 24시간 등급을 1시간 등급으로 바꾸지 않음.
- 공개 제보의 숨김·다른 지역·미래·3시간 만료 제외. 익명 읽기는 명시적으로 켜야 하고, 기존 익명 쓰기 5개 경로는 production에서 403.
- HTTP 검증은 모든 공급자 키와 DB 키를 비운 상태에서 실행. 날씨·대기질·장소·제보에 임의의 실시간 값을 넣지 않는지 확인.

## 의존성 보안: 배포 전 해결 필요

이번 점검에서 lockfile의 의존성 그래프에 대해 **critical 5 / high 32 / moderate 19 / low 2**가 보고되었다. 취약 버전의 포함을 확인한 결과이며, 이 앱에서 해당 공격을 재현했다는 의미는 아니다.

업데이트 후보를 준비했지만 새 의존성 설치가 다음 도구 오류로 완료되지 않았다.

```text
network approval was cancelled before a decision was returned
```

이후 네트워크를 쓰지 않는 설치도 필요한 캐시가 없어 실패했다. 그래서 manifest·lockfile·의존성을 원래 버전과 일치하는 상태로 복원하고 위 기능 검증을 진행했다. **취약점이 수정되었다고 판단하거나 현재 브랜치를 운영 공개하면 안 된다.**

다음 작업과 미검증 패치는 [의존성 업데이트 기록](dependency-upgrade.md)에 정리했다. 기존 lockfile SHA-256:

```text

```

4. 대기질 측정소 연결과 공개 제보를 켤 경우 운영 데이터·RLS·삭제/신고 대응을 확인한다.
5. 운영 트래픽 제한·공급자 쿼터·배포 설정을 확인한 뒤 기본 브랜치 병합과 공개 배포를 결정한다.
