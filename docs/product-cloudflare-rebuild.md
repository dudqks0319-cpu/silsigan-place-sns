# #실시간 Cloudflare 전국 MVP 제품/UX 운영 기준

기준일: 2026-06-18  
대상 전환: Next.js/Vercel/Supabase 중심 MVP에서 Cloudflare Pages/Workers, D1, R2, KV 또는 Cache API 기반 무료 출시 구조로 재정의한다.

## 1. 제품 목표

`#실시간`은 전국 주요 장소의 지금 상태를 빠르게 확인하고, 현장에 있는 사용자가 10초 안에 사진/상태를 제보할 수 있는 위치 기반 현장 확인 서비스다.

무료 출시 기준의 목표:

- 전국 단위 탐색을 제공하되, 초기 데이터 품질이 낮은 지역은 빈 상태와 제보 유도를 명확히 보여준다.
- 정확한 사용자 좌표, 원본 IP, EXIF/GPS, 원본 파일명을 저장하지 않는다.
- 장소 좌표가 검증되지 않은 seed는 임의 좌표로 채우지 않고 `TODO_COORDINATE_VERIFY` 상태로 둔다.
- 사진/댓글/제보 신고와 자동 숨김이 준비되기 전에는 공개 사용자 업로드를 열지 않는다.
- 병원/관공서처럼 민감정보 위험이 높은 카테고리는 사진/댓글 정책을 더 보수적으로 적용한다.

## 2. MVP 범위

### 포함

| 영역 | MVP 기준 |
| --- | --- |
| 홈 | 전국 실시간 랭킹, 내 주변 또는 선택 지역, 지금 질문 올라온 곳, 빈 상태 안내 |
| 지역 | 시/도, 시/군/구, 주요 area 단위 필터 |
| 장소 상세 | 장소명, 주소, 카테고리, 최근 3시간 제보, 댓글, 사진, 질문, 신고 |
| 지도 | 장소 좌표 기준 핀, 현재 map bounds 내 랭킹, 사용자 정확 좌표 미표시 |
| 제보 | 혼잡도, 줄 상태, 주차 상태, 체감 날씨, 한 줄 코멘트, 사진 0~1장, 위치 인증 |
| 질문 | 장소별 질문 등록, 사진 요청 질문 구분 |
| 신고/운영 | 댓글/사진/제보 신고, 3회 자동 숨김, 관리자 숨김/복구/삭제 |
| 저장소 | D1: 구조화 데이터, R2: 재인코딩 이미지, KV/Cache: 랭킹 캐시 |

### 제외

- 결제, 현금성 포인트, 유료 광고, 업체 관리자 상품
- DM, 팔로우 기반 소셜 네트워크
- 네이티브 앱 전용 기능
- AI 자동 판독 또는 자동 모자이크 의존 출시
- 검증되지 않은 전국 장소 자동 대량 노출
- 사용자 이동 경로, 방문 이력, 정확 좌표 기반 히스토리
- 원본 사진 파일 보관

## 3. 화면 구조

### 홈

- 상단: 검색, 지역 선택, 위치 권한 CTA.
- 첫 영역: 전국 실시간 랭킹 10개.
- 두 번째 영역: 선택 지역 랭킹 또는 내 주변 랭킹.
- 세 번째 영역: 사진 제보가 있는 장소.
- 네 번째 영역: 답변을 기다리는 질문.
- 빈 상태: 지역/카테고리/위치 권한별 안내를 분리한다.

홈 카피:

- 헤드라인: `지금 가도 괜찮은지, 현장 제보로 확인하세요.`
- 서브카피: `혼잡도, 줄, 주차, 사진을 최근 3시간 기준으로 보여줍니다.`
- 위치 CTA: `내 주변 보기`
- 위치 설명: `정확한 좌표는 저장하지 않고 장소와의 거리 구간만 확인합니다.`

### 온보딩

온보딩은 3단계 이하로 제한한다.

1. `전국 장소의 지금 상태`
   - `여행지, 병원, 관공서, 주차장 상황을 최근 제보 기준으로 확인합니다.`
2. `현장에 있다면 10초 제보`
   - `사진 없이도 혼잡도와 주차 상태만 빠르게 남길 수 있습니다.`
3. `개인정보는 보수적으로`
   - `사람 얼굴, 차량번호, 문서, 정확 좌표는 저장하거나 노출하지 않습니다.`

### 지역/Area

- 지역 depth: `전국 > 시/도 > 시/군/구 > area`.
- area는 행정구역, 관광권, 상권, 행사장 권역처럼 운영자가 정의한다.
- area에 연결된 장소 수가 5개 미만이면 `탐색 가능`이 아니라 `준비 중`으로 표시한다.

### 장소 상세

- 상단: 장소명, 카테고리, 주소, 최근 업데이트 시각.
- 상태 요약: 혼잡도, 줄, 주차, 사진 수, 질문 수.
- 탭: 제보, 사진, 댓글, 질문.
- CTA: `현장 제보`, `근처 사용자에게 질문`.
- 신고 진입: 각 댓글/사진/제보의 더보기 메뉴.

### 지도

- 지도 핀은 장소 좌표만 사용한다.
- 사용자 좌표는 화면 중심 계산에만 쓰고 마커로 표시하지 않는다.
- map bounds 랭킹은 현재 화면 안의 장소만 대상으로 한다.
- 좌표 미검증 장소는 지도에 노출하지 않고 목록에서 `좌표 검증 필요`로만 운영자에게 표시한다.

## 5. 초기 Seed 전략

### 원칙

- seed는 `verified`, `TODO_COORDINATE_VERIFY`, `rejected` 상태를 가진다.
- 주소와 좌표가 모두 신뢰 가능한 출처로 확인된 장소만 지도/랭킹에 공개한다.
- 좌표가 확실하지 않은 장소는 임의 좌표를 만들지 않는다.
- 좌표 미검증 장소는 D1에 넣더라도 `coordinate_status = "TODO_COORDINATE_VERIFY"`로 저장하고 공개 지도 응답에서 제외한다.
- 병원/관공서는 장소명/주소가 정확해도 사진 제보 UX에 민감정보 경고를 먼저 붙인다.

### Seed 최소 기준

| 단위 | 공개 전 최소 기준 |
| --- | --- |
| 시/도 | 검증된 장소 30개 이상 또는 대표 area 3개 이상 |
| 시/군/구 | 검증된 장소 10개 이상 |
| area | 검증된 장소 5개 이상 |
| 카테고리 | 지역 내 검증된 장소 3개 이상 |

### Seed 데이터 필드

| 필드 | 기준 |
| --- | --- |
| `place_id` | 사람이 읽을 수 있는 slug + 충돌 방지 suffix |
| `name` | 공식 명칭 또는 현장 표기 |
| `region_code` | 행정구역 코드 또는 내부 지역 slug |
| `area_id` | 운영자가 정의한 area slug |
| `category` | `tourism`, `festival_event`, `restaurant_cafe`, `hospital`, `public_office`, `parking` |
| `address` | 공개 주소. 개인 주소 금지 |
| `lat`, `lng` | 장소 좌표만 허용. 불확실하면 null |
| `coordinate_status` | `verified`, `TODO_COORDINATE_VERIFY`, `rejected` |
| `source_note` | 출처명만 기록. 민감 URL/token 저장 금지 |

### 초기 노출 방식

- 전국 홈은 검증된 seed만 노출한다.
- seed만 있고 최근 제보가 없는 장소는 `최근 제보 없음` 상태로 표시한다.
- 랭킹은 seed 수가 아니라 최근 제보/질문/사진 신호가 있어야 진입한다.
- 지역별 seed 품질이 낮으면 “준비 중 지역”으로 표기하고 제보 CTA보다 지역 선택/알림 CTA를 우선한다.

## 6. 릴리즈 게이트

### P0 무료 출시 차단

- Cloudflare Pages/Workers 배포 URL에서 홈, 지역, 장소 상세, 신고 API가 정상 응답한다.
- D1 migration과 seed import가 재실행 가능하다.
- R2 업로드는 EXIF/GPS 제거와 재인코딩 후의 파일만 저장한다.
- 원본 IP, 원본 파일명, 원본 좌표, EXIF/GPS가 D1/R2/KV/log 응답에 남지 않는다.
- 댓글/사진/제보 신고 3회 자동 숨김이 동작한다.
- 관리자 API는 운영자 권한 없이는 숨김/복구/삭제를 수행하지 못한다.
- 병원/관공서 카테고리는 제출 전 민감정보 경고가 표시된다.
- 빈 지역, 빈 댓글, 빈 사진, 빈 랭킹, 위치 권한 거부 UX가 구현되어 있다.
- `pnpm test`, `pnpm typecheck`, `pnpm lint`가 통과한다.

### P1 출시 후 보완

- area별 운영자 대시보드.
- 악용 사용자 rate limit 세분화.
- 지역 활성화 알림.

## 7. 구현자 전달 메모

- `ranked_places` 응답은 숨김/만료/좌표 미검증 장소를 제외해야 한다.
- 장소 좌표 검증이 끝나지 않은 경우 `lat/lng`를 0, 0 또는 지역 중심점으로 대체하지 않는다.
- 위치 권한 거부 사용자는 읽기와 상태 제보는 가능하지만 `현장 인증` 배지는 받을 수 없다.
- 신고/삭제 UX는 “삭제 요청 접수”와 “운영자 삭제 완료” 상태를 분리한다.
