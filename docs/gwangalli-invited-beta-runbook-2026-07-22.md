# #실시간 광안리 초대형 베타 실행 런북

Updated: 2026-07-22
Status: local execution packet; no participant contacted; no paid marketing; production unchanged

## 1. 목적과 범위

광안리 지정 장소에서 10명이 5일 동안 하루 최대 2회 핵심 흐름을 사용해 제품의 신뢰성, 사용성, 운영 가능성을 검증한다. 베타는 staging에서만 진행하며 다음 행위를 승인하지 않는다.

- production 배포 또는 설정 변경
- 공개 모집, 언론 배포, 인플루언서 게시 또는 유료 광고
- 보상·포인트·경품 약속
- Turnstile 우회, 자동 사진 업로드 또는 반복 제보로 수치 채우기
- 광안리 밖 지역 확장

seed 목표 `30개 장소·최근 제보 100건·위치 확인 30건·승인 사진 30건·검수 준비`는 `src/lib/domain.ts`의 `regionActivationThresholds`와 일치한다. 최대 100건은 `10명 × 하루 최대 2건 × 5일`의 운영 상한이며 성공을 미리 보장하지 않는다.

## 2. 시작 승인 게이트

아래 항목이 하나라도 미완료면 모집 안내를 발송하지 않는다.

- [ ] 동일 source SHA의 staging web/API 주소와 점검 일시를 운영표에 기록했다.
- [ ] 실제 사진이 없을 때 `최근`, `방금 전`, 현장 사진처럼 보이는 fallback을 노출하지 않는다.
- [ ] 사람이 Turnstile을 통과한 사진 업로드→검수→공개 읽기→숨김/삭제→잔여 0건 증거가 있다.
- [ ] 검수 담당과 비상 연락 담당이 D1~D5 운영 시간에 지정됐다.
- [ ] `docs/ugc-moderation-runbook.md`의 queue, SLA, hide/delete/restore 경로를 리허설했다.
- [ ] `docs/privacy-safety-policy.md`의 위치·사진·민감 장소 제한을 참여 안내에 반영했다.
- [ ] 개인정보 처리방침, 이용약관/UGC 조건, 지원·삭제 요청 경로와 실제 운영자 연락처를 법률 담당이 확인했다.
- [ ] 참가자 연령 정책이 정해졌고, 별도 적법성 검토 전에는 성인만 참여한다.
- [ ] analytics 수신과 redaction을 staging에서 확인했다.
- [ ] 비용·트래픽·신고 stop condition과 중단 담당을 지정했다.

## 4. 참여 안내와 확인

### 4.1 초대 문구

> 광안리의 최근 현장 근거를 안전하게 모으는 5일 초대형 베타입니다. 하루 최대 2회 지정 장소의 상태를 확인하고, 선택적으로 사진 1장을 제보합니다. 사진에는 얼굴·차량번호·문서·결제정보가 없어야 하며, 본인이 촬영했거나 게시할 권리가 있는 사진만 제출할 수 있습니다. 모든 사진은 공개 전 검수됩니다. 앱은 현장 상태의 정확성이나 지속 시간을 보장하지 않습니다. 참여 중 불편하거나 삭제를 원하면 안내된 지원 경로로 요청할 수 있습니다.

### 4.2 참여 전 확인표

- [ ] staging 테스트이며 공개 서비스·정확도 검증 완료를 뜻하지 않음을 확인했다.
- [ ] 5일 일정, 하루 최대 2회, 자발적 중단 가능성을 확인했다.
- [ ] 위치는 현장 근처 여부 확인에 사용되며 원본 좌표를 운영 공유표에 기록하지 않음을 확인했다.
- [ ] 사진 권리, 공개 전 검수, 신고·숨김·삭제 절차를 확인했다.
- [ ] 얼굴·차량번호·신분증·영수증·진료/민원 문서·결제정보 촬영 금지를 확인했다.
- [ ] 촬영 금지 표시, 사유지, 통행 방해, 위험 구간에서는 촬영하지 않기로 했다.
- [ ] 병원·관공서에서는 사람·문서·번호판이 보이는 사진이나 개인 방문을 추정할 문장을 제출하지 않기로 했다.
- [ ] 실제 지원·삭제 요청 경로를 받았다.
- [ ] 성인 참여 조건 또는 법률 담당이 승인한 연령 절차를 충족했다.

이 체크리스트는 법적 동의서나 법률 자문을 대체하지 않는다. 법률 담당이 승인한 문서와 충돌하면 승인 문서를 우선하고 베타를 중단한다.

## 5. 장소와 슬롯 준비

30개 장소 운영표에는 다음 최소 필드만 둔다.

| 필드 | 규칙 |
| --- | --- |
| place ID·표시명 | 앱의 검증된 장소와 일치 |
| 카테고리 | 민감 장소 여부 판정에 사용 |
| 장소 좌표 검증 상태 | `verified`만 seed gate에 포함 |
| 촬영 제한 | 실내 금지, 사유지, 사람 밀집, 병원·관공서 등 |
| 오전/오후 슬롯 | 오전 08:00~11:00, 오후 16:00~20:00 |
| 담당 참여자 | 별칭 또는 운영용 번호; 공개 공유표에 연락처 금지 |
| 결과 | 미실행·제출·승인·거절·숨김·삭제 중 하나 |

원본 좌표, 원본 파일명, 익명 ID, 전화번호, 이메일, 자유서술 개인정보는 공동 운영표에 적지 않는다.

## 6. 일일 운영

### D0 — 오리엔테이션

1. 참여 안내와 안전 확인표를 읽는다.
2. staging 주소와 테스트 기기·브라우저 범위를 확인한다.
3. 사진이 없는 장소에서 `최근 확인 정보 없음`이 보이는지 확인한다.
4. 위치 권한 거부 시에도 읽기와 수동 지역 선택이 가능한지 확인한다.
5. 사진 제출은 사람 Turnstile 경로만 사용하고 자동화를 시도하지 않는다.

### D1~D5 — 참여자 과업

각 참여자는 하루 최대 2개 슬롯에서 다음 순서로 진행한다.

1. 홈 또는 추천에서 정보 유무를 판단한다.
2. 장소 상세를 열고 장소명·관측시각·출처를 확인한다.
3. 지정 장소와 실제 위치가 일치할 때만 상태를 제보한다.
4. 선택적으로 안전한 사진 1장을 올리고 게시 권리 확인을 직접 선택한다.
5. 공개 전 검수 상태를 확인한다.
6. 잘못된 장소, 오해되는 최신성, 접근성·네트워크 문제를 운영자에게 알린다.

### 운영자 시간표

| 시각 | 실행 | 완료 증거 |
| --- | --- | --- |
| 08:00 | 당일 담당·슬롯·stop condition 확인 | 기명 운영 체크 |
| 11:00 | 1차 검수와 민감정보 우선 hide | queue counts와 처리 시각 |
| 18:00 | 2차 검수, 신고·삭제 요청 확인 | SLA 집계 |
| 20:00 | seed·KPI·incident·비용 상태 집계 | aggregate-only 일일표 |
| 종료 후 | 다음날 지속·축소·중단 판정 | 제품·검수·보안 확인 |

### D6~D12 — 후속 관찰

- 신규 제보 목표를 강제로 채우지 않고 D7 재방문 분모가 성립할 때까지 관찰한다.
- 삭제·신고·incident와 공개 잔여 데이터를 확인한다.
- D7이 계산되기 전에는 5일 현장 운영이 끝나도 확장 판정을 내리지 않는다.

## 7. KPI 정의

분모가 0이면 비율을 0%로 만들지 말고 `측정 불가`로 기록한다. 거절률은 검수 결과이며 허위 제보율로 해석하지 않는다.

| KPI | 공식 | 근거 |
| --- | --- | --- |
| 핵심 방문 판단 성공률 | 정보 유무를 올바르게 판별한 과업 수 ÷ 해당 과업 시도 수 × 100 | 진행자 과업표 |
| 추천→장소 상세 진입률 | 추천/홈 노출 뒤 장소 상세에 진입한 과업 수 ÷ 추천/홈 노출 과업 수 × 100 | 진행자 과업표. 현재 analytics 계약에는 추천 노출 분모 이벤트가 없어 자동 집계로 주장하지 않음 |
| 제보 완료율 | `report_submitted` 수 ÷ `report_started` 수 × 100 | `/api/admin/beta-kpis?days=7` |
| D1 재방문율 | 최초 `app_opened` 후 1일 시점 재방문 사용자 수 ÷ 대상 사용자 수 × 100 | aggregate-only beta KPI |
| D7 재방문율 | 최초 `app_opened` 후 7일 시점 재방문 사용자 수 ÷ 대상 사용자 수 × 100 | aggregate-only beta KPI |
| 검수 24시간 SLA | 24시간 안에 approved/rejected/hidden 처리한 건수 ÷ pending을 제외한 검토 완료 건수 × 100 | aggregate-only beta KPI |
| fresh coverage | 현재 공개 live signal이 있는 verified beta/active 장소 수 ÷ eligible 장소 수 × 100 | aggregate-only beta KPI |
| 오인율 | 사진 없는 상태를 최근 사진으로 판단한 과업 수 ÷ 사진 없는 상태 과업 수 × 100 | 진행자 과업표 |
| seed 장소 | 검증된 지정 장소 수 | 지역 운영표 |
| 최근 제보 | D1~D5 제출 제보 수 | 운영 집계 |
| 위치 확인 제보 | 실제 위치 확인 성공 제보 수 | 운영 집계 |
| 승인 사진 | 검수 상태가 approved인 사진 연결 제보 수 | moderation 집계 |

다음 통과선을 함께 본다.

- 핵심 방문 판단 성공률 90% 이상
- 추천→장소 상세 진입률 30% 이상
- 제보 완료율 60% 이상
- D7 재방문율 20% 이상
- 검수 24시간 SLA 95% 이상
- 최근 사진 오인 0건
- seed gate 30/100/30/30/검수 준비 5개 모두 통과

10명 표본의 수치는 방향성 검증용이며 시장 전체 성과나 통계적 유의성을 주장하지 않는다. D7은 D1 참여자의 7일 후 관찰이 끝난 뒤 계산하므로 5일 현장 운영 종료와 베타 최종 판정일을 구분한다.

## 8. Analytics 수신·redaction 확인

실제 값을 채우기 전 다음 체크리스트만 사용한다. raw request body나 사용자별 event row를 공유 증거로 저장하지 않는다.

- [ ] staging 앱에서 `app_opened`, `report_started`, `report_submitted` 중 승인된 테스트 이벤트를 발생시켰다.
- [ ] `/api/analytics/events`가 `202`, `accepted: true`, 허용된 `eventName`을 반환했다.
- [ ] 운영자 전용 `/api/admin/beta-kpis?days=7`에서 aggregate-only 응답이 갱신됐다.
- [ ] 응답에 actor identifier 또는 개별 event properties가 없음을 확인했다.
- [ ] token, secret, authorization, cookie, password, memo, comment, caption, note, coordinate, latitude, longitude, clientLocation, filename, error, stack, digest, location, anonymousId, anonId, adminSubject가 원문으로 남지 않았다.
- [ ] 이메일, 익명 ID 형식, JWT, API key, 이미지·문서 파일명이 `[redacted]` 처리되는지 확인했다.
- [ ] Workers tail 증거에는 raw IP, 원좌표, 원본 파일명, token, cookie, request body가 없다.
- [ ] 공유 artifact에는 source SHA, 환경, 일시, HTTP status, aggregate count와 redaction 결과만 남겼다.

이 문서는 admin credential 또는 실제 URL을 기록하지 않는다. 운영자는 기존 secret 관리와 deny-by-default admin 경로를 사용한다.

## 9. Incident·비용·법률 중단 조건

다음 중 하나라도 발생하면 신규 과업과 모집을 즉시 중단한다.

### 안전·개인정보

- 얼굴·차량번호·문서·결제정보·개인 방문 사실 노출
- 숨김/삭제 요청이 public surface와 사진 read 경로에 반영되지 않음
- 원본 좌표, 원본 IP, 원본 파일명, token, 익명 ID 또는 request body가 로그·artifact에 노출
- 촬영 금지 장소, 사유지 침해, 통행 방해 또는 참여자 안전 위험

### 운영·신뢰

- 사진 없는 상태가 실제 최근 사진처럼 보임
- 민감정보 queue 즉시 triage 또는 24시간 검수 SLA를 지킬 운영자가 없음
- 신고·hide·delete·restore 경로가 작동하지 않음
- staging이 아닌 production 또는 승인되지 않은 환경에 연결됨

### 비용·보안

- 사진 관련 비용 meter 중 하나가 80% stop에 도달
- 비정상 트래픽, identifier rotation, 반복 업로드 또는 retry storm 경보
- WAF·rate limit·budget·kill switch 상태를 확인할 수 없음
- Turnstile 우회나 자동화 시도

### 법률·마케팅

- 개인정보·UGC·위치정보·미성년자 절차의 법률 담당 중단 요청
- 운영자 연락처·삭제 요청 경로 부재
- 승인되지 않은 공개 모집, paid campaign, 보상 약속 또는 성과 주장
- 권리 없는 사진 또는 상표·시설 촬영 제한 위반 의심

중단 후에는 incident ID, 시각, 영향 범위, 노출 중단 여부, 잔여 데이터·비용, 담당자, 재개 조건만 redacted 형태로 기록한다. 제품·법률·보안 담당이 원인과 잔여 위험을 확인하기 전 재개하지 않는다.

## 10. 종료와 확장 판정

### 종료 보고

- 계획 10명과 실제 참여 수를 분리한다.
- 계획 100건과 실제 제출·승인·거절·숨김·삭제 수를 분리한다.
- 분모가 0이거나 관측하지 못한 KPI는 `미검증`으로 남긴다.
- local test, staging 행동, 실기기, 사람 확인, production 상태를 별도 표로 보고한다.
- incident와 삭제 요청이 모두 닫히지 않으면 베타를 완료로 표시하지 않는다.

### 확장 후보 조건

다음 조건을 모두 만족해야 다음 지역의 초대형 베타를 제안할 수 있다.

1. seed gate 5/5 통과
2. D7 재방문율 20% 이상
3. 추천→장소 상세 진입률 30% 이상
4. 검수 24시간 SLA 95% 이상
5. 최근 사진 오인 0건
6. 열린 개인정보·안전·법률·비용 incident 0건
7. 법률·보안·제품 책임자의 기명 승인

통과는 production, 공개 모집 또는 유료 마케팅의 자동 승인이 아니다. 각 변경은 별도 release gate와 승인을 거친다.
