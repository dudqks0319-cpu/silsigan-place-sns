# #실시간 개인정보/위치정보/사진 안전 정책

기준일: 2026-06-18
대상 구조: Cloudflare Pages/Workers, D1, R2, KV 또는 Cache API.

## 1. 개인정보 처리 원칙

- MVP는 서비스 제공에 필요한 최소 정보만 수집한다.
- 사용자의 정확한 현재 좌표는 공개하지 않는다.
- 위치 인증에 사용한 원본 좌표는 검증 직후 폐기하고 D1/KV/R2/로그에 저장하지 않는다.
- 원본 IP는 저장하지 않는다. abuse control이 필요하면 회전 salt 기반 해시처럼 원본 복원이 불가능한 값만 제한 기간 사용한다.
- 사진 원본 파일명, EXIF, GPS, 촬영 기기, 촬영 시각은 저장/노출하지 않는다.
- 원본 업로드 파일은 보관하지 않고 재인코딩된 안전 variant만 R2에 저장한다.
- 민감정보가 포함된 콘텐츠는 신고 접수 즉시 숨김 또는 제한 노출을 우선 적용한다.

## 2. Cloudflare 저장소별 금지/허용 데이터

| 저장소 | 저장 금지 | 저장 허용 |
| --- | --- | --- |
| D1 | 사용자 원본 위도/경도, 원본 IP, 원본 파일명, EXIF/GPS, 이동 경로, 방문 이력 | 장소 ID, 장소 좌표, 거리 구간, 제보 상태, 신고 상태, 운영 감사 최소 필드 |
| R2 | 원본 사진, 원본 파일명, EXIF/GPS 포함 파일, 얼굴/문서/번호판 식별 사진 | 재인코딩 이미지, 썸네일, 랜덤 object key |
| KV/Cache | 원본 좌표, 원본 IP, 신고 상세 원문, 비밀키 | 랭킹 결과, 장소 요약, 캐시 생성 시각, privacy-safe empty copy |
| Workers logs | request body 원문, 좌표, 토큰, 원본 IP, 원본 파일명 | 요청 ID, 응답 코드, redacted error code, latency |

로컬 redaction guard:

- Worker generic error 응답은 안전한 public code만 반환하고 하위 계층 error message 원문을 echo하지 않는다.
- 브라우저 analytics console 출력은 토큰, raw coordinate, 익명 ID, 원본 파일명, 이메일을 `[redacted]`로 치환한다.
- Cloudflare staging에서는 별도로 `wrangler tail` 또는 dashboard 로그 샘플을 확인해 플랫폼 로그에도 원문이 남지 않는지 증적을 남긴다.

## 3. 위치정보 정책

### 수집 목적

- 사용자가 특정 장소 근처에서 제보했는지 확인한다.
- 주변 제보를 거리 구간 기준으로 정렬/표시한다.
- 지도 화면의 중심 또는 bounds 계산을 수행한다.

### 저장 금지

- 사용자 원본 위도/경도.
- GPS EXIF.
- 이동 경로 또는 방문 이력.
- 로그/분석 도구에 raw coordinate 전송.
- map bounds 요청에서 사용자의 정확 위치를 추정 가능한 형태로 장기 저장.

### 저장 허용

- 장소 ID.
- 위치 인증 여부.
- 거리 구간: `50m 이내`, `50-150m`, `150-300m`, `범위 밖`.
- 인증 시각.
- 3시간 만료 시각.
- 장소 좌표. 단, seed 좌표가 검증된 경우만 공개 응답에 포함한다.

### 사용자 노출

- `장소 근처 인증됨`, `약 150m 이내` 같은 구간 표현만 표시한다.
- 지도에는 사용자 좌표가 아니라 장소/제보 대상 위치만 표시한다.
- 위치 권한 거부 시 읽기와 지역 선택은 허용하고, 현장 인증 배지만 제한한다.

위치 권한 거부 카피:

- 제목: `위치 권한 없이도 볼 수 있습니다`
- 본문: `지역을 직접 선택해 둘러볼 수 있어요. 현장 인증 제보에는 위치 확인이 필요합니다.`
- CTA: `지역 선택하기`

## 4. 사진 업로드 정책

- 업로드 가능한 형식은 JPEG/WebP로 제한한다.
- SVG, HTML, 실행 가능한 파일, MIME 위장 파일은 금지한다.
- Worker는 R2 저장 전 JPEG EXIF/XMP/comment metadata와 WebP EXIF/XMP chunk를 제거한다.
- 클라이언트는 1280px 이하로 재인코딩한 파일만 완료 등록할 수 있으며, Worker는 R2 저장 전 metadata 제거 후 Cloudflare Images binding으로 서버 픽셀 재인코딩을 수행한다.
- R2 object key는 랜덤 ID를 사용하고 원본 파일명을 포함하지 않는다.
- GPS, 촬영 기기, 촬영 시각, 원본 파일명은 저장/노출하지 않는다.
- 얼굴, 차량번호, 신분증, 영수증, 진료/민원 문서, 결제정보가 보이는 사진은 금지한다.
- 문제 사진은 신고 접수 시 우선 숨김 처리 후 운영자가 검토한다.

빈 사진 카피:

- 제목: `최근 사진 제보가 없습니다`
- 본문: `사람 얼굴, 차량번호, 문서가 보이지 않는 현장 사진만 올려 주세요.`
- CTA: `사진 제보하기`

## 5. 댓글/제보 안전 정책

- 댓글은 200자 이하, 제보 코멘트는 120자 이하를 권장한다.
- 전화번호, 주민등록번호, 접수번호, 차량번호, 계좌, 주소 등 개인정보 패턴은 서버에서 차단하거나 검토 플래그를 붙인다.
- 병원/관공서 장소의 댓글은 특정 개인 방문 사실을 추정할 수 있는 문장을 금지한다.
- 신고 3회 누적 시 자동 숨김 처리한다.

빈 댓글 카피:

- 제목: `아직 댓글이 없습니다`
- 본문: `현장 상황을 본 사람이 짧게 남기면 다른 방문자가 바로 참고할 수 있어요.`
- CTA: `댓글 남기기`

## 6. 병원/관공서 민감정보 제한

병원/관공서 카테고리는 다음 업로드와 댓글을 금지한다.

- 환자, 보호자, 민원인, 직원의 얼굴이 식별되는 사진.
- 환자명, 접수번호, 대기번호, 주민등록번호, 전화번호, 주소.
- 진료 서류, 처방전, 민원 서류, 신분증, 명찰, 차량번호.
- 특정 개인의 방문 사실을 추정할 수 있는 사진 또는 코멘트.

제품 UX 요구:

- 제출 전 민감정보 경고를 별도 표시한다.
- 병원/관공서 사진은 `사람/문서/번호판이 보이면 업로드 금지` 문구를 표시한다.
- 민감 카테고리 신고는 일반 신고보다 높은 우선순위로 운영한다.

## 7. 신고 정책

신고 유형:

- 개인정보 노출.
- 얼굴/차량번호 노출.
- 병원/관공서 민감정보.
- 허위 위치/허위 사진.
- 광고/스팸.
- 폭력/혐오/불법 정보.
- 기타.

처리 원칙:

- 명백한 개인정보/민감정보 신고는 먼저 숨기고 나중에 판단한다.
- 댓글/사진/제보는 신고 3회 누적 시 자동 숨김 처리한다.
- 신고자와 피신고자의 개인정보는 서로 공개하지 않는다.
- 반복 허위 제보자는 신뢰도 감점, 질문권 제한, 계정 제한을 적용할 수 있다.
- 신고 악용 사용자는 신고 기능 제한을 적용할 수 있다.

권장 SLA:

- 개인정보/민감정보: 접수 즉시 자동 숨김 또는 운영자 긴급 확인, 24시간 내 최종 판단.
- 병원/관공서 민감정보: 접수 즉시 자동 숨김, 12시간 내 최종 판단.
- 허위/스팸: 72시간 내 검토.
- 긴급 삭제 요청: 운영자 알림 채널로 즉시 전달. 알림 payload에는 신고 ID, 대상 ID, 사유, 우선순위, 큐 경로만 포함하고 신고자 ID, note 원문, 원좌표, 원본 파일명은 포함하지 않는다.

## 8. 삭제/보관 정책

- 제보는 기본 3시간 후 만료되어 공개 목록에서 제외된다.
- 작성자 삭제 요청 시 공개 노출을 즉시 중단한다.
- 운영자 삭제 시 D1 레코드 상태, R2 파일, 썸네일, KV/Cache를 함께 정리한다.
- 법적 분쟁 또는 악용 조사 목적의 최소 감사 로그만 제한 기간 보관한다.
- 감사 로그에는 raw coordinate, 원본 IP, 사진 원본 메타데이터, 원본 파일명을 저장하지 않는다.

## 10. 운영자 체크리스트

- [x] 민감 신고 큐 운영자 알림 채널은 redacted payload만 전송하도록 구현/테스트되어 있다.
- [ ] staging/production `MODERATION_ALERT_WEBHOOK_URL` secret이 실제 운영 채널로 등록되어 있는지 확인한다.
- [ ] 민감 신고 큐를 매일 확인한다.
- [ ] 병원/관공서 신고는 우선 처리한다.
- [ ] 삭제 처리 후 R2 사진 URL이 더 이상 접근되지 않는지 확인한다.
- [ ] 반복 악용 계정의 제보/질문/신고 패턴을 검토한다.
- [ ] Workers 로그에 위치 원본, 원본 IP, 원본 파일명, 비밀키가 남지 않는지 주기 점검한다.
- [x] 좌표 미검증 seed가 지도/랭킹 API에 노출되지 않는지 자동 테스트로 확인한다.
