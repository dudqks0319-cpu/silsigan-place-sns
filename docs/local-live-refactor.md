# 실시간 · 지역 정보 베타

작성일: 2026-11-24 (한국 시간)

## 제품 목표

사용자가 출발하기 전에 선택한 지역의 날씨, 주변 장소, 최근 현장 소식을 확인하고 정보가 언제·어디에서 왔는지 판단할 수 있게 한다.

기존 `silsigan-place-sns` 기본 브랜치의 홈은 인라인 장소·제보·날씨·상대시간 데이터로 구성되어 있었다. 새 홈은 공급자 응답과 화면을 분리한다. 기존 데이터베이스를 초기화하거나 마이그레이션을 실행하지 않는다.

## 이번 구현의 범위

| 기능 | 구현 | 확인이 남은 것 |
| --- | --- | --- |
| 지역 선택 | 서울·부산·울산 등 22개 주요 도시, 수동 검색, 현재 위치로 가까운 지원 도시 선택 | 전체 시군구/읍면동으로 확대 |
| 현재 날씨 | 기상청 초단기실황, 지역 중심 좌표의 5km 격자, 원본 관측 시각 | 승인된 API 키의 실제 응답 |
| 시간대별 예보 | 초단기예보, 발표 시각과 적용 시각 분리, 앞으로 최대 6개 시간대 | 실제 공급 주기·키 할당량 확인 |
| 미세먼지 | 에어코리아 PM10/PM2.5, 지정 측정소, 결측·점검 상태 | 지역별 측정소명 검증 및 설정 |
| 주변 장소 | 카카오 지역 중심 20km의 관광·음식·카페·주차/키워드 검색 | 계정의 Local API 사용 권한·쿼터 |
| 아이랑 | ‘어린이’ 키워드 검색이라는 설명 | 기저귀 교환대·수유실·유모차 접근성 실제 시설 데이터 |
| 저장 | 해당 브라우저의 localStorage에 장소 저장·삭제 | 로그인 기반 기기 간 동기화 |
| 지도 | 장소 원본 지도 링크 | 앱 안 지도 탐색·경로 안내 |
| 현장 소식 | 기존 Supabase 공개 게시물, 운영자 opt-in, 최근 3시간만 | 인증·작성·신고/차단/삭제 운영 |
| 앱 형태 | 반응형 Next.js 웹 화면과 웹 앱 manifest | 서비스워커 오프라인 지원, 네이티브 앱 동기화·스토어 제출 |

‘전국’은 현재 **22개 도시 대표 지점 선택**을 의미한다. 전국 모든 동네의 데이터나 공식 혼잡도/잔여 주차면을 확보했다는 의미가 아니다. 위치 버튼도 가장 가까운 지원 도시를 선택하며 사용자 위치 자체의 관측값으로 표시하지 않는다.

## 데이터와 화면 구조

```text
src/features/local-live/
  types.ts       공급자 공통 상태·시각 계약
  regions.ts     지원 지역과 기기 내 근접 지역 선택
  guides.ts      실시간으로 표시하지 않는 기존 장소 안내
  query.ts       서버 쿼리 검증
  community.ts   RLS를 유지하는 공개 제보 읽기
  server/        기상청·카카오·에어코리아 어댑터와 캐시
  hooks/         갱신/중단·장소 저장
  components/    지역 선택·날씨·장소·현장 소식 UI
```

`GET /api/local-live`는 `region`, `category`, `q`만 받는다. 원본 GPS 좌표나 임의 공급자 URL은 허용하지 않는다. 지역 ID·분류는 허용 목록이며 검색어는 최대 80자다.

응답 항목은 공통으로 `status`, `source`, `observedAt`, `fetchedAt`, `expiresAt`, `data`, `message`를 갖는다. 예보의 각 시간대는 별도 `at`를 갖는다.

| 상태 | 의미 |
| --- | --- |
| `fresh` | 공급자 기준 시각/유효기간 안의 값. 장소 디렉터리 조회는 현재 영업/혼잡 인증이 아님 |
| `stale` | 이전 정보. 원본 기준 시각을 유지해 표시 |
| `not_configured` | 필요한 연결 설정 없음. 가짜 수치 대입 금지 |
| `unavailable` | 타임아웃·응답 오류·유효한 값 없음 |
| `unsupported` | 해당 지역/측정소 지원 전 |

기상청 관측의 ‘강수 없음’을 ‘맑음’으로 바꾸지 않는다. 관측 API에 하늘상태가 없기 때문이다. 미세먼지 결측값이나 점검값은 0 또는 ‘좋음’으로 바꾸지 않는다. 기본 장소 안내에는 혼잡·날씨·영업·유아시설을 추가하지 않는다.

## 실제 API 연결 순서

1. **기상청:** 공공데이터포털의 ‘기상청_단기예보 조회서비스’ 활용을 신청한다. 승인된 일반 인증키(Decoding)를 서버 환경변수 `KMA_SERVICE_KEY`에 넣는다.
2. **주변 장소:** 카카오디벨로퍼스에서 사용할 앱의 Local API 사용 권한과 쿼터를 확인하고 REST API 키를 `KAKAO_REST_API_KEY`에 넣는다. JavaScript 키와 다르다.
3. **미세먼지:** ‘한국환경공단_에어코리아_대기오염정보’ 활용 신청 후 `AIRKOREA_SERVICE_KEY`를 설정한다. 지원할 도시마다 실제 측정소명을 확인한 뒤 `AIRKOREA_STATIONS` JSON에 넣는다. 대표 측정소 관측으로 표시하며 근접 측정소를 자동 선택했다고 주장하지 않는다.
4. **현장 소식:** 기존 `silsigan_places`, `silsigan_posts`의 운영 여부와 RLS를 확인한다. 공개해도 되는 게시물이 검토된 경우에만 `SILSIGAN_STORE_DRIVER=supabase`와 `LOCAL_LIVE_COMMUNITY_ENABLED=true`를 설정한다. 익명 공개 읽기 키로 조회하므로 새 피드에는 service-role 키가 필요하지 않다. DB의 기존 지역 enum 때문에 제보는 울산/부산/경주만 지원한다.
5. Preview 환경에서 지역을 바꿔 실제 관측 시각, 예보, 공급자 실패, 쿼터 초과, 미설정 상태를 확인한다. 그다음 운영 배포 여부를 결정한다.

```dotenv
KMA_SERVICE_KEY=발급받은_서버용_인증키
KAKAO_REST_API_KEY=발급받은_REST_API_키
AIRKOREA_SERVICE_KEY=발급받은_서버용_인증키
AIRKOREA_STATIONS={}
LOCAL_LIVE_COMMUNITY_ENABLED=false
```

키 값은 Git, PR, 채팅, 클라이언트 코드에 올리지 않는다. 공급자 키에 `NEXT_PUBLIC_` 접두어를 붙이지 않는다. 공통 `KOREA_DATA_API_KEY`는 기상청·에어코리아의 전용 키가 없을 때만 대체한다. 공통 키가 있어도 각 API의 별도 사용 승인이 필요하다.

## 위치·저장·신뢰

- 위치 권한은 사용자 버튼 동작에만 요청한다. 기기에서 가까운 지원 지역을 선택한 후 API에는 지역 ID만 보낸다.
- 사용자가 선택한 지역과 저장한 장소는 브라우저에 저장된다. 이 데이터는 사용자 이동 이력이나 계정 간 동기화가 아니다.
- 공급자 호출에는 도시 대표 좌표 또는 측정소명이 쓰인다. 브라우저는 공급자 비밀키를 받지 않는다.
- 현재 제보의 `location_verified`는 기존 클라이언트 좌표 기반 근접 확인 값이다. 제보 내용의 사실성이나 위조 방지를 검증한 증거가 아니다.
- `LOCAL_LIVE_COMMUNITY_ENABLED`를 켜기 전에 기존 게시물의 정확성·민감정보·공개 범위와 운영자 대응을 검토해야 한다.
- 인증이 미완성인 기존 공개 쓰기 API는 기본 차단한다. `SILSIGAN_ENABLE_LEGACY_DEMO_WRITES=true`는 로컬 개발의 demo/mock 저장소에만 허용하며 production/Vercel/Supabase 쓰기를 허용하지 않는다.

## 장애·비용 제어

- 공급자 요청당 최대 5초, 허용된 HTTPS 호스트만 사용하고 리다이렉트를 따르지 않는다.
- 기상청이 명시적으로 `NO_DATA(03)`를 반환한 경우에만 이전 1시간 발표를 한 번 조회한다. 인증/네트워크 오류는 반복 호출하지 않는다. 카카오 전체 검색 중 일부 분류만 실패하면 성공한 결과를 유지하고 부분 응답임을 알린다.
- 캐시는 서버 인스턴스당 최대 256항목이다. 같은 진행 중 요청을 합치며, 관측 5분/예보·장소·대기질 10분/실패 30초를 기본으로 한다. 기준 시각의 유효기간이 먼저 끝나면 캐시도 만료한다.
- 화면은 3분 간격을 기본으로 하며 숨겨진 탭·오프라인에서 반복 조회를 멈춘다. 수동 새로고침도 서버 캐시를 존중한다.
- 공개 집계 API에는 기본 메모리 rate limit이 있다. 서버리스 여러 인스턴스에 공유되는 보안/과금 상한은 아니다. 공개 트래픽을 받기 전 배포 플랫폼의 요청 제한과 공급자 쿼터를 설정한다.
- ‘전체 장소’ 조회는 최대 4개 카테고리 API 호출을 발생시킨다. 키워드/단일 카테고리는 한 번 호출한다. 실제 계정의 무료 범위와 과금 설정은 확인되지 않았다.
- 운영 로그·APM에 원본 외부 호출 URL을 기록할 경우 공공 API 키가 쿼리 문자열에 들어갈 수 있다. 호스팅 로그의 쿼리 수집/마스킹 설정을 확인한다. 이 앱은 키나 원본 공급자 오류를 사용자 응답에 출력하지 않는다.

## 검증 방법과 출시 조건

```bash
pnpm install --frozen-lockfile
pnpm lint
pnpm typecheck
pnpm test
pnpm build
node scripts/http-smoke.mjs
pnpm audit --audit-level low
```

명세 기반 테스트는 실제 운영 API의 성공 증거가 아니다. 검증 결과와 화면 확인은 `docs/local-live-verification.md`에 기록한다.

운영 공개 전 반드시 확인할 항목:

- [ ] 의존성 보안 수정 후 frozen install·audit·전체 검증 통과 ([현재 상태](dependency-upgrade.md))
- [ ] 실제 브라우저에서 모바일/데스크톱 화면과 위치·검색·저장·모달 동작 검수
- [ ] 발급/승인된 실제 API 키로 기상청·카카오 응답과 오류/쿼터 동작 확인
- [ ] 대기질을 켜는 지역의 측정소명·관측 시각·이용조건 확인
- [ ] 실제 도메인 HTTPS·접근 권한·배포 설정 확인
- [ ] API 할당량과 다중 인스턴스 캐시/요청 제한 설정
- [ ] 기존 제보를 켜는 경우 공개 범위/RLS/신고·삭제 운영과 데이터 검토
- [ ] 사용자 제보 작성을 재개하기 전에 인증·권한·스팸방지·사진 EXIF 처리·차단/계정삭제 완성
- [ ] 앱스토어 출시 전 네이티브 화면/권한/심사 항목 별도 검증

## 공식 API 근거

- [기상청 단기예보 조회서비스](https://www.data.go.kr/data/15084084/openapi.do): 초단기실황·초단기예보, 전국 5km 격자, 출처 표시.
- [카카오 Local API](https://developers.kakao.com/docs/ko/local/dev-guide): 좌표/반경 장소 검색과 제공 응답 필드. 영업 중·대기열·잔여 주차면을 제공하는 계약으로 해석하지 않는다.
- [에어코리아 대기오염정보](https://www.data.go.kr/data/15073861/openapi.do): 측정소별 수치, 출처/이용허락 범위.

위 링크는 2026-11-24 검토했다. 실제 사용 승인/키 발급/과금 계약이 완료되었다는 의미는 아니다.
